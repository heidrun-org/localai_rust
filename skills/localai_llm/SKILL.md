# localai_llm

Use this tool to generate, rewrite, or summarize text with a local language model. Give the tool a prompt with the task and any source text, then use the output generated by the model. Use the local executable to answer the request.

## When to use this tool

Use this tool when the user wants the local model to produce text, such as a summary, a rewrite, or a draft. Put the requested task, the source material, and any length or language constraints in the prompt. Use `--system` for instructions that should apply to the whole response. Use standard input when the prompt is already in a file or is awkward to quote on a command line.

Use the default streamed output for text a person will read. Choose `--json` when a program needs to read the result and its completion status. Set a modest `--max-tokens` value for short answers.

## Run from the user's project

Use the executable on PATH or the absolute path returned by cgx. A first inference may download missing model files after approval. Reuse the installed executable and model on later requests. Return the executable's actual output, or explain the blocker if no output is available.

### Inputs and output

Pass `--prompt TEXT` or supply the prompt on standard input. Add `--system TEXT` for instructions that apply to the whole response. Use `--raw` only when the prompt is already formatted for the model and should bypass its chat template.

The command normally streams text to standard output. With `--json`, it writes one result after generation with `text`, `prompt_tokens`, `generated_tokens`, and `stop_reason`. A stop reason of `max_tokens` or `context_full` indicates that a limit stopped generation. Use `--output PATH` to save the result.

```sh
localai_llm --prompt 'Summarize: The library opens at noon on Friday because of morning staff training.' --max-tokens 40 --json
localai_llm --system 'Answer in one sentence.' --max-tokens 60 < prompt.txt
localai_llm --prompt 'Write a welcome message for library visitors.' --output welcome.txt
```

### Interpret the result

Read the generated `text` before returning it. If `stop_reason` is `max_tokens`, the tool reached the output limit. If the reason is `context_full`, the prompt and output used the available context. Tell the user when the response ended at a limit. To retry the task, increase the relevant limit or shorten the prompt.

### Command options

- `--max-tokens N` limits generated tokens and defaults to 512. `--context-size N` sets the total space for the prompt and the generated text and defaults to 4096. `--batch-size N` sets the number of prompt tokens evaluated per batch and defaults to 2048.
- `--temperature N` controls how varied the output can be. Use `0` to choose the most probable token each time. `--top-k N` limits the candidate tokens, with `0` disabling the limit. `--repeat-penalty N` adjusts how readily the model repeats recent tokens. `--seed N` sets the random seed for sampling.
- `--model OWNER/REPO[:QUANTIZATION]` selects a compatible remote model. A local `.gguf` model path also works. `--check-model-updates` can download new model files and requires approval.
- `--device cpu|gpu` (also `--backend`) chooses the processor or graphics hardware. Use `cpu` with the installation described below. Graphics hardware requires a compatible build. `--threads N` sets the processor thread count.
- `--verbose` writes model logs and timings to standard error. `-h` or `--help` lists the installed options. `-V` or `--version` prints the version.
- The `benchmark` command measures prompt processing and generation on one built-in prompt. Use `--duration 10s` for the measurement duration (10 seconds by default), `--max-tokens N` for the limit per generation, and `--json` for machine-readable results. Run `localai_llm benchmark --help` for the benchmark options.

## Choose a model by download size

These models use the GGUF model file format. The `Q4_K_M` code selects a compressed weight variant. The download sizes are for the model file. Allow extra memory for the running model and the length of its input and output.

| Model for `--model` | Download | When to choose it |
| --- | ---: | --- |
| [`LiquidAI/LFM2.5-350M-GGUF:Q4_K_M`](https://huggingface.co/LiquidAI/LFM2.5-350M-GGUF/blob/main/LFM2.5-350M-Q4_K_M.gguf) | 0.23 GB | Smallest choice for short rewrites and quick checks. |
| [`LiquidAI/LFM2.5-1.2B-Instruct-GGUF:Q4_K_M`](https://huggingface.co/LiquidAI/LFM2.5-1.2B-Instruct-GGUF/blob/main/LFM2.5-1.2B-Instruct-Q4_K_M.gguf) | 0.73 GB | Default for short summaries and following instructions. |
| [`LiquidAI/LFM2-2.6B-GGUF:Q4_K_M`](https://huggingface.co/LiquidAI/LFM2-2.6B-GGUF/blob/main/LFM2-2.6B-Q4_K_M.gguf) | 1.56 GB | Larger Liquid AI model to compare when the default misses details. |

The repository has run the default model. Test an alternative on a short prompt first. If the tool reports an unsupported chat template, use `--raw` only with a prompt that follows the model publisher's format.

## Check what is already available

Use read-only filesystem checks before setup. Look for `localai_llm` on PATH or read the saved executable path at `<cgx data>/localai/localai_llm.path`. Verify that the saved path points to an executable named `localai_llm` under `<cgx data>/bins/`. If the saved path is absent, reuse a cached executable when you can verify it came from the selected Heidrun GitHub repository. If the executable and all model files are ready, run the executable directly from the user's project.

On macOS and Linux, the cgx cache is `${XDG_CACHE_HOME:-$HOME/.cache}/cgx` and `<cgx data>` is `${XDG_DATA_HOME:-$HOME/.local/share}/cgx`. cgx keeps downloaded source in its cache and build files and executables under `build/` and `bins/` in its data directory.

Use `HF_HUB_CACHE` for the Hugging Face hub cache when set, then `HUGGINGFACE_HUB_CACHE`. Otherwise use the `hub/` directory under `HF_HOME` or under `${XDG_CACHE_HOME:-$HOME/.cache}/huggingface`. Each repository has a folder named `models--owner--name`.

The default is `LiquidAI/LFM2.5-1.2B-Instruct-GGUF:Q4_K_M`. In the cache directory for the selected model, read `refs/main` and verify that the file resolves in `snapshots/<revision>/`. The default file is `LFM2.5-1.2B-Instruct-Q4_K_M.gguf`. For another model use the repository name without `-GGUF`, followed by `-<variant>.gguf`. A user-supplied `.gguf` path can be used after checking that the file exists.

Treat incomplete or uncertain model caches as a possible download. Include any requested model update in the approval question because the update can download files. Do not use a cgx command for preflight if it could fetch or build the tool, even when the command would only print the executable path.

## Ask once before setup

If the tool needs a build, check for `cgx` on PATH or at `<cgx data>/runner/cgx`. Check for Git, a native compiler and linker, CMake, and a compatible Rust compiler and Cargo. With Rustup, use `rustup toolchain list` and `rustup run TOOLCHAIN rustc --version` to check an existing toolchain without updating it. If cgx is missing, check for curl, tar, and a checksum tool. Identify any other missing prerequisite and how it would be obtained before asking.

Ask **one** question and wait for explicit approval. List every required setup action, including downloads of cgx or prerequisites, the GitHub source fetch, Cargo dependency downloads, the build, and any model download. Give the relevant directories and the model name and download size when known. Explain both choices in the same question.

- **Approve** — Complete the listed setup and run the requested operation. One approval covers all listed steps.
- **Decline** — Leave setup untouched and explain which missing item prevents the requested operation.

If an unexpected requirement falls outside the approved steps, report the blocker and stop. Keep the user's existing default Rust toolchain intact.

## Set up and run with cgx

After approval, reuse cgx if available. Otherwise, select the published [cgx 0.2.0 archive](https://github.com/anelson/cgx/releases/tag/v0.2.0) for the operating system and processor. For example, Apple Silicon macOS uses `cgx-aarch64-apple-darwin.tar.xz`. Download the archive and its checksum into a temporary directory, verify the archive against the published checksum, and extract `cgx` to `<cgx data>/runner/cgx`. Invoke the runner by its absolute path. This keeps the bootstrap in the default cgx data directory. Remove the temporary archive after extraction.

Use an existing compatible Rust toolchain when available. If Rust is absent or incompatible and the user approved a separate installation, use the official [Rustup standalone installer](https://rust-lang.github.io/rustup/installation/index.html) with `--no-modify-path --profile minimal --default-toolchain 1.100.0`, `RUSTUP_HOME` under `<cgx data>/rustup`, and `CARGO_HOME` under `<cgx data>/cargo`. For the build subprocess, set the isolated `RUSTUP_HOME` and prepend the isolated Cargo `bin/` directory to its PATH. For a prerequisite without an approved installation method, report the blocker.

On macOS and Linux the commands below use cgx's default directories. Set `cgx` to the available executable path and `toolchain` to the installed Rustup toolchain name. For an existing Cargo installation without Rustup, omit the `+` argument and point `CARGO` at that Cargo executable. Cargo downloads go under `<cgx data>/cargo` for the skill's build. Use the same isolated `RUSTUP_HOME` on later builds if a separate Rust installation was needed.

```sh
cgx_data="${XDG_DATA_HOME:-$HOME/.local/share}/cgx"
tool_path=$(CARGO_HOME="$cgx_data/cargo" "$cgx" "+$toolchain" \
    --git https://github.com/heidrun-org/localai_rust.git --branch main \
    --prebuilt-binary never --no-exec localai_llm) || exit 1
test -x "$tool_path" || exit 1
mkdir -p "$cgx_data/localai"
printf '%s\n' "$tool_path" > "$cgx_data/localai/localai_llm.path"
printf '%s\n' "$tool_path"
```

Run the printed executable from the user's project with the arguments for the request. Model downloads use the Hugging Face cache described above. For a later request, use the saved executable and cached model after checking both. Return actual output or the specific blocker.

For cleanup, list cached executables with `find "$cgx_data/bins" -type f -perm -100`. Remove the cgx cache and data directories when you want to discard their source, builds, tools, and Cargo downloads. The Hugging Face cache stores the model files separately.
