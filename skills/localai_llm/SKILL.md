# localai_llm

Use this tool to generate, rewrite, or summarize text with a local language model. Give the tool a prompt with the task and any source text, then use the output generated by the model. Use the local executable to answer the request.

## When to use this tool

Use this tool when the user wants the local model to produce text, such as a summary, a rewrite, or a draft. Put the requested task, the source material, and any length or language constraints in the prompt. Use `--system` for instructions that should apply to the whole response. Use standard input when the prompt is already in a file or is awkward to quote on a command line.

Use the default streamed output for text a person will read. Choose `--json` when a program needs to read the result and its completion status. Set a modest `--max-tokens` value for short answers.

## Run from the user's project

Use the executable on PATH or the absolute path printed by the setup commands. A first inference may download missing model files after approval. Reuse the installed executable and model on later requests. Return the executable's actual output, or explain the blocker if no output is available.

### Inputs and output

Pass `--prompt TEXT` or supply the prompt on standard input. Add `--system TEXT` for instructions that apply to the whole response. Use `--raw` only when the prompt is already formatted for the model and should bypass its chat template.

The command normally streams text to standard output. With `--json`, it writes one result after generation with `text`, `prompt_tokens`, `generated_tokens`, and `stop_reason`. A stop reason of `max_tokens` or `context_full` indicates that a limit stopped generation. Use `--output PATH` to save the result.

```sh
localai_llm --prompt 'Summarize: The library opens at noon on Friday because of morning staff training.' --max-tokens 40 --json
localai_llm --system 'Answer in one sentence.' --max-tokens 60 < prompt.txt
localai_llm --prompt 'Write a welcome message for library visitors.' --output welcome.txt
```

### Interpret the result

Read the generated `text` before returning it. If `stop_reason` is `max_tokens`, the tool reached the output limit. If the reason is `context_full`, the prompt and output used the available context. Tell the user when the response ended at a limit. To retry the task, increase the relevant limit or shorten the prompt.

### Command options

- `--max-tokens N` limits generated tokens and defaults to 512. `--context-size N` sets the total space for the prompt and the generated text and defaults to 4096. `--batch-size N` sets the number of prompt tokens evaluated per batch and defaults to 2048.
- `--temperature N` controls how varied the output can be. Use `0` to choose the most probable token each time. `--top-k N` limits the candidate tokens, with `0` disabling the limit. `--repeat-penalty N` adjusts how readily the model repeats recent tokens. `--seed N` sets the random seed for sampling.
- `--model OWNER/REPO[:QUANTIZATION]` selects a compatible remote model. A local `.gguf` model path also works. `--check-model-updates` can download new model files and requires approval.
- `--device cpu|gpu` (also `--backend`) chooses the processor or graphics hardware. Use `cpu` with the installation described below. Graphics hardware requires a compatible build. `--threads N` sets the processor thread count.
- `--verbose` writes model logs and timings to standard error. `-h` or `--help` lists the installed options. `-V` or `--version` prints the version.
- The `benchmark` command measures prompt processing and generation on built-in prompts. Use `--generations N` for the number of generations per case, `--max-tokens N` for the limit per generation, and `--json` for machine-readable results. Run `localai_llm benchmark --help` for the benchmark options.

### Find the executable and model

Look for `localai_llm` on PATH and at `<setup directory>/bin/localai_llm`. The setup directory is `LOCALAI_SETUP_DIR` when set, otherwise `${XDG_DATA_HOME:-$HOME/.local/share}/heidrun-localai-rust`. If the executable and model are ready, run the executable directly.

The default model is `LiquidAI/LFM2.5-1.2B-Instruct-GGUF` (about 0.73 GB). Resolve the cache as `HF_HUB_CACHE`, then `HUGGINGFACE_HUB_CACHE`, then the `hub` directory under `HF_HOME` or under the Hugging Face cache in `XDG_CACHE_HOME` (default `~/.cache`). In the repository's `models--owner--name` cache directory, read `refs/main` and check that the following files resolve under `snapshots/<revision>/`: LFM2.5-1.2B-Instruct-Q4_K_M.gguf. A user-supplied local `.gguf` file can be used with `--model` after checking it exists. For a different model check its exact repository and files. Treat an uncertain or incomplete cache as a possible download.

Use filesystem reads for these checks. Even a partial cache can trigger a download. Leave model update checks off unless the user requests and approves them.

## Ask before setup

If a build is needed, check for Git, a native compiler and linker, and CMake. Look for mise on PATH and at `<setup directory>/bin/mise`. If mise is missing, check for curl on macOS or Linux. If the managed Rust toolchain is missing, include the Rust download. For a missing prerequisite, identify the installation command or explain what the human needs to do if the environment prevents setup.

Ask the human for explicit approval before installing a prerequisite, fetching source, building, or downloading a model. List only the needed steps, the setup directory, and the model name and size when known. Explain mise when it needs installation:

> Mise can download and run the tools a command needs without adding them to your usual shell setup. It keeps the downloads for reuse.

Ask “May I proceed with these steps?” and wait. On refusal, leave setup untouched. Ask again if an additional setup step turns out to be necessary.

## Install the executable with mise

When the executable is missing, run the following in a fresh POSIX shell after approval. The commands reuse mise if available or install the official release on macOS and Linux. Rust and Cargo use a dedicated setup directory. Mise fetches and builds only this package from GitHub.

```sh
# Stop on errors or unset variables so setup cannot continue after a failed step.
set -eu
package=localai_llm
# Keep downloads and builds in a dedicated directory. An absolute path still
# points to the same place after the script changes its working directory.
setup_dir="${LOCALAI_SETUP_DIR:-${XDG_DATA_HOME:-$HOME/.local/share}/heidrun-localai-rust}"
case "$setup_dir" in
    /*) ;;
    *) echo 'LOCALAI_SETUP_DIR must be an absolute path.' >&2; exit 2 ;;
esac

# If the managed executable already exists, report its path and skip setup.
if [ -x "$setup_dir/bin/$package" ]; then
    printf '%s\n' "$setup_dir/bin/$package"
    exit
fi

# Reuse mise from PATH or from this setup directory before downloading it.
mkdir -p "$setup_dir/$package" "$setup_dir/bin"
if command -v mise >/dev/null 2>&1; then
    mise_bin="$(command -v mise)"
else
    mise_bin="$setup_dir/bin/mise"
    if [ ! -x "$mise_bin" ]; then
        case "$(uname -s)" in
            Darwin|Linux) ;;
            *) echo 'Install mise for this platform and put it on PATH. See https://mise.jdx.dev/installing-mise.html' >&2; exit 1 ;;
        esac
        # Download the official installer to a temporary file and remove that
        # file when the shell exits. Install mise without shell activation.
        installer="$(mktemp "$setup_dir/mise-installer.XXXXXX")"
        trap 'rm -f "$installer"' EXIT
        curl -fsSL https://mise.run -o "$installer"
        MISE_INSTALL_PATH="$mise_bin" MISE_VERSION=v2026.11.12 MISE_INSTALL_HELP=0 sh "$installer"
    fi
fi

# Run mise from the package setup directory. Keep mise data, Cargo files,
# and Rust toolchains separate from the user's normal configuration.
cd "$setup_dir/$package"
export MISE_DATA_DIR="$setup_dir/mise-data"
export MISE_CACHE_DIR="$setup_dir/mise-cache"
export MISE_CONFIG_DIR="$setup_dir/mise-config"
export MISE_STATE_DIR="$setup_dir/mise-state"
export CARGO_HOME="$setup_dir/cargo"
export CARGO_TARGET_DIR="$setup_dir/target"
export RUSTUP_HOME="$setup_dir/rustup"
export MISE_RUST_CARGO_HOME="$CARGO_HOME"
# Trust the setup directory for this run so mise can read the file below.
export MISE_TRUSTED_CONFIG_PATHS="$PWD"
# Pin the Rust version and the Git revision. The crate name selects just
# the requested executable from the repository.
cat > mise.toml <<EOF
[tool_alias]
$package = "cargo:https://github.com/heidrun-org/localai_rust"

[tools]
rust = "1.100.0"
$package = { version = "rev:a77075be2e6d981ea5eb6588d2695728b4da59dd", crate = "$package" }
EOF
# Let mise fetch the source and build the executable with Cargo.
"$mise_bin" install --jobs 1
# Give later requests a stable executable path that works from any project.
executable="$("$mise_bin" where "$package")/bin/$package"
test -x "$executable"
ln -sfn "$executable" "$setup_dir/bin/$package"
printf '%s\n' "$setup_dir/bin/$package"
```
